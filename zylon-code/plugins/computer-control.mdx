Computer control lets the agent inspect and operate Desktop applications through Cua Driver. This experimental capability needs explicit setup and is separate from browser automation and file tools.

## Prepare the integration

Ask your administrator or Creator to configure one compatible Cua Driver provider. The native provider uses its platform SDK; the MCP alternative uses a separately installed `cua-driver` executable. Your build and operating system determine which is supported.

Grant the required operating-system permissions to Zylon Code or the application that launches its local runtime. For screenshot-based work, choose a model that supports image input.

## Inspect before interacting

> Find the application window I specify and inspect its current state. Describe what you see without clicking or typing.

Check that the correct window was found. Then request a bounded action and inspect fresh state afterward.

The desktop is shared with your own actions and other sessions. Cancelling does not reverse clicks or input already sent. Before retrying, check whether the previous action took effect.

Use file and shell tools for ordinary coding when graphical interaction is unnecessary. For runtime failures or missing permissions, follow [tool troubleshooting](/zylon-code/troubleshooting/tools-and-permissions).
