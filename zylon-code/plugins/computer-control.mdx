Computer control lets the agent inspect and operate Desktop applications through Cua Driver. It is useful when a task needs interaction with a graphical application, such as checking a window or filling in a form. This experimental feature requires setup separately from browser automation and file tools.

## Prepare the integration

Ask your administrator or Creator to configure one compatible Cua Driver provider. The MCP option requires a separately installed `cua-driver` executable. Your build and operating system determine which is supported.

Grant the required operating-system permissions to Zylon Code or the application that launches its local runtime. For screenshot-based work, choose a model that supports image input.

On macOS 14 or later, your administrator can also prepare the experimental native macOS provider. It is not enabled in the normal installation. It requires application consent as well as Accessibility and Screen Recording permissions; a locked desktop prevents observations and input. Ask which provider your supplied build supports before granting access.

## Inspect before interacting

> Find the application window I specify and inspect its current state. Describe what you see without clicking or typing.

Check that the correct window was found. Then request a bounded action and inspect fresh state afterward.

The desktop is shared with your own actions and other sessions. Cancelling does not reverse clicks or input already sent. Before retrying, check whether the previous action took effect.

Use file and shell tools for ordinary coding when graphical interaction is unnecessary. For runtime failures or missing permissions, follow [tool troubleshooting](/zylon-code/troubleshooting/tools-and-permissions).
