The Backoffice API exposes platform-level endpoints for authorized operators and automation jobs. Use it for operational workflows that are outside the Workspace API, such as manually retrieving Zylon logs for investigation or export.

## Base URL

Backoffice endpoints are served from the platform root:

```http
https://{BASE_URL}
```

Unlike Workspace API routes, Backoffice routes documented here do not use the `/api/v1/app` workspace prefix.

## Authentication and permissions

Backoffice API requests require an account token or account session with at least the `operator` role. An account token can use `Read.All` when its owner role also grants the requested Backoffice permission; `Read.All` never elevates the owner. `ReadWrite.All` also includes read access.

```bash
-H "Authorization: Bearer {API_TOKEN}"
```

<Note>
Workspace-only and gateway-scoped ZylonGPT tokens are not enough for Backoffice endpoints. Interactive sessions continue to use their role permissions and are not restricted by API token scopes.
</Note>

See [Token Management](/en/developer-manual/get-started/token-management) for the complete scope model.
