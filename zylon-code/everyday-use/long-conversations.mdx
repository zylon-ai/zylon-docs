A model can only work with a limited amount of information at once. This is its **context window**. Messages, instructions, available tools and their results all take up space. Long tool output may be shortened, so ask the agent to inspect a specific file or section when a detail matters.

## Compact a conversation

Standard, PTC, Minimal and Creator include compaction. Use **Compact** in the command menu or `/compact` when available. Compaction replaces part of the information sent to the model with a summary. It preserves the project files and conversation history, so you can still inspect the original tool results.

Run manual compaction when the agent is idle. If the summary fails or is truncated, the selected original history is retained; inspect the error and check the model's [context and output limits](/zylon-code/models/model-options) before retrying. Compaction can also happen automatically as context fills.

## Preserve what matters

Before continuing, ask for a concise handoff:

> Summarize the goal, files changed, decisions, checks run, unresolved failures and the next concrete step. Include paths so I can verify the state.

Keep durable project rules in [instructions](/zylon-code/customization/project-instructions), and reusable workflows in [skills](/zylon-code/customization/skills). Use the original tool result or changed file to verify completed work; the summary is an aid to continuing the task.

## Start a fresh task

Use a new conversation for an unrelated objective. A fork can retain useful history but shares files unless you prepare another checkout. Check current files and jobs after interruption or restart; earlier model descriptions can be stale. [Recovery](/zylon-code/troubleshooting/recovery) explains what to inspect.
