## ¿Qué token necesito?

  <Card title="Token de Workspace" icon="briefcase">

    Automatiza operaciones de Workspace — crea proyectos, gestiona usuarios, interactúa con archivos ingestados y más.
  </Card>
  <Card title="Token de Gateway" icon="bolt">

<Tabs>
  <Tab title="Token de Workspace">
    Este flujo es para el acceso a la **API de Workspace** bajo `/api/v1/*`.

    <Warning>
      El flujo de token de Workspace **no** emite tokens para llamadas directas a la API de ZylonGPT bajo `/api/gpt/v1/*`.
    </Warning>

    ### Crea un token de API de Workspace

    1. Inicia sesión en Workspace con una cuenta que pueda gestionar tokens de API.
    2. Haz clic en el logo de la organización y abre **API Tokens**.
    3. Haz clic en **Create API Token**, proporciona un nombre y guarda.
    4. Copia y almacena el valor del token inmediatamente. Se muestra solo una vez.

    ![](/images/api-reference/images/token.png)
    ![](/images/api-reference/images/create-token.png)

    ### Verifica el acceso del token

    Los endpoints de Workspace bajo `/api/v1/app/*` requieren el header `x-org`.

    ```bash
    curl "https://{BASE_URL}/api/v1/app/me" \
      -H "Authorization: Bearer {API_TOKEN}" \
      -H "x-org: {org_slug}"
    ```

    <Accordion title="Ejemplo de respuesta">

        "id": "user_4b7c2a1d9e5f3c8b",

    Abre **API Tokens** y haz clic en el icono de papelera en la fila del token.

## Scopes de token de API

La creación de tokens de cuenta acepta estos seis valores serializados de scope:

| Scope | Acceso |
| --- | --- |
| `Read.All` | Lectura de cuentas, tokens, gateways, Backoffice/metadatos y Workspace, búsqueda en Workspace y allowlist de solo lectura de ZylonGPT cuando el token incluye `gateway_id`. |
| `ReadWrite.All` | Lectura y escritura en las APIs, según los roles de la cuenta propietaria. |
| `Workspace.Read.All` | Lecturas y búsquedas de Workspace; las mutaciones de Workspace devuelven `403`. |
| `Workspace.ReadWrite.All` | Operaciones de lectura y escritura de Workspace. |
| `PrivateGPT.Read.All` | Solo la allowlist de ZylonGPT de lectura para el gateway seleccionado. |
| `PrivateGPT.ReadWrite.All` | Operaciones de lectura y escritura de ZylonGPT para el gateway seleccionado. |

Si un token tiene varios scopes, sus permisos se combinan. Después, los permisos efectivos se limitan a los permisos de la cuenta y el rol propietarios del token. Un scope amplio no puede elevar a su propietario y un token de API de solo lectura sigue restringido aunque su propietario sea SuperAdmin. Estas restricciones de scope solo se aplican a tokens de API; las sesiones interactivas no cambian.

<Note>
  Si una solicitud de token de cuenta omite `scopes`, se usa `Workspace.ReadWrite.All` por defecto. Enviar un array `scopes` vacío de forma explícita devuelve `400`. Tanto `PrivateGPT.Read.All` como `PrivateGPT.ReadWrite.All` requieren `gateway_id`.
</Note>

`Read.All` no requiere `gateway_id` al crear el token. Sin ese contexto de gateway, el token puede usar sus demás permisos de lectura, pero no puede llamar a ZylonGPT.

La creación de tokens de gateway solo acepta `PrivateGPT.Read.All` y `PrivateGPT.ReadWrite.All`; solicitar otro scope devuelve `400`. Por compatibilidad, el endpoint de tokens de gateway convierte una lista de scopes legacy vacía explícita en `PrivateGPT.ReadWrite.All`.

Consulta la [visión general de ZylonGPT API](/es/developer-manual/build-with-zylon/zylon-gpt-api/overview) para ver la lista de endpoints de solo lectura y los requisitos de lectura y escritura.
