La Workspace API te permite gestionar por API **todo lo que ocurre en Zylon Workspace**: organizaciones, miembros del espacio de trabajo, proyectos, chats, artefactos, integraciones e informes. Úsala para automatizar tareas de administración o integrar Zylon con tus sistemas internos.

## Base URL

Todos los endpoints de Workspace viven bajo:

```
https://{BASE_URL}/api/v1
```

## Cabecera de organización (`x-org`)

Los endpoints de Workspace bajo `/api/v1/app/*` requieren la cabecera `x-org` para que Zylon sepa a qué organización del workspace apuntar.

Puedes enviar `x-org` como:

- el slug de la organización (recomendado), por ejemplo `default`
- el ID de la organización (UUID)

Úsalo así en tus solicitudes:

```bash
-H "x-org: {org_slug}"
```

## Scopes de token de solo lectura

`Workspace.Read.All` permite lecturas y búsquedas de Workspace, incluidas organizaciones, miembros del espacio de trabajo, proyectos, artefactos, hilos, interacciones, incidencias, feedback e integraciones. No permite mutaciones de Workspace; las operaciones de creación, actualización, eliminación, unión y otras escrituras devuelven `403`.

`Read.All` incluye los mismos permisos de lectura/búsqueda de Workspace y también inventario de cuentas, tokens y gateways y lecturas de Backoffice/metadatos. Su [allowlist de solo lectura de ZylonGPT](/es/developer-manual/build-with-zylon/zylon-gpt-api/overview) solo se puede usar cuando el token de cuenta incluye `gateway_id`; un token `Read.All` creado sin contexto de gateway no puede llamar a ZylonGPT. El acceso efectivo siempre queda limitado por los permisos de rol del propietario del token. Los scopes múltiples combinan sus permisos. Consulta [Gestión de tokens](/es/developer-manual/get-started/token-management) para ver los seis scopes y las reglas de creación.

## Conceptos clave

| Concepto | Significado |
| --- | --- |
| **Cuenta (`Account`)** | Registro de identidad que se autentica en Zylon. Una cuenta puede pertenecer a varias organizaciones. |
| **Miembro del espacio de trabajo (`WorkspaceMember`)** | Membresía de una cuenta dentro de una organización. Una cuenta puede tener **varios miembros del espacio de trabajo**, uno por organización. |
| **Artefacto (`Artifact`)** | Contenido persistente que puede reutilizarse en chats y herramientas. |

Este modelo permite escenarios multi‑organización en los que una misma persona puede pertenecer a varios espacios de trabajo con roles distintos.

## Paginación

La paginación es un modelo compartido en la Workspace API. Los listados devuelven un sobre con cursores:

<Accordion title="Ejemplo de sobre de paginación">
```json
{
  "data": [],
  "next_cursor": "cursor_next",
  "previous_cursor": "cursor_prev",
  "has_next_page": false,
  "has_previous_page": false,
  "total_count": 0
}
```
</Accordion>

Usa `page`, `page_size`, `after`, `before`, `first`, `last` y `total_count` cuando estén disponibles.

## Errores y casos límite

- **401/403**: token ausente o permisos insuficientes.
- **404**: IDs inválidos o eliminados.
- **Redirecciones**: login/callback devuelven `302` para navegadores.
