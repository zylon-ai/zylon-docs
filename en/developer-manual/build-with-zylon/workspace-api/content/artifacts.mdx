title: "Artifacts"
description: "Workspace artifacts for documents, AI Documents, and connectors."
---

An artifact is a piece of information **or tool** you provide to Zylon so it can be used as context for queries and operations. The Workspace API groups artifacts into **document artifacts**, **AI Documents**, and **other artifacts**.

## Prerequisites

- An API token. See [Workspace Token Management](/en/developer-manual/get-started/token-management).
- Your Zylon hostname (replace `{BASE_URL}` in the examples).

## Artifacts

| Category | Includes | When to use |
| --- | --- | --- |
| **Document artifacts** | Documents, folders, links | Store or organize content inside an organization or project. |
| **AI Documents** | Summary, composition, extraction flows | Run workflows across artifacts to produce outputs. |
| **Other artifacts** | MCP servers, SQL databases, integrations, skills | Provide external tools, data sources, or reusable instructions. |

### Artifact request fields

Use `POST /api/v1/app/artifact` to create any artifact type. Ownership is supplied in the request body rather than the path. When you send `x-org`, omit `organization_id` and optionally set `project_id`; without `x-org`, Operator and SuperAdmin callers may set `organization_id`. A `project_id` always belongs to the selected organization. Set `project_id` to `null` (or omit it) to create an organization artifact; this requires an AppAdmin or higher role, and `Link` artifacts always require a project.

<Accordion title="Artifact request fields">
| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `organization_id` | string | Conditional | Organization identifier. Omit it when using `x-org`; otherwise it is available only to Operator and SuperAdmin callers. |
| `project_id` | string \| null | No | Project identifier. Omit it or set it to `null` for an organization artifact. Required for `Link`. |
| `type` | string | Yes | Artifact type: `Document`, `Folder`, `Summary`, `Composition`, `SmartDoc`, `Link`, `BulkQA`, `ReadAndExtract`, `SqlDatabase`, `McpServer`, `Integration`, `Analysis`, or `Skill`. |
| `name` | string | Yes | Artifact display name. |
| `props` | object | Yes | Type-specific configuration. The legacy alias `config` is also accepted. |
| `source` | string | No | Artifact source. Production values are `User`, `SharePoint`, `GoogleDrive`, `Confluence`, `ConfluenceLocalLegacy`, `Claromentis`, `FileSystem`, `Assistant`, and `System`. Defaults to `User`. |
| `description` | string | No | Human-readable description. |
| `parent_id` | string | No | Parent artifact ID for tree artifacts such as documents, folders, and links. Do not use it for MCP or database artifacts. |
| `integration_id` | string | No | Integration ID for integration-backed artifacts. The legacy alias `integration_artifact_id` is also accepted. |
| `external_url` | string | No | External URL for link-like or connector-backed artifacts. |
| `content` | string | Conditional | Base64-encoded content in JSON create requests. A successful `Document` or `Skill` create requires either this field or multipart `file_data`. |
| `keep_file_after_ingestion` | boolean | No | Whether uploaded file data should be retained after ingestion. Defaults to `true`. |
| `interaction_id` | string | No | Interaction that produced this artifact, when applicable. |
| `private_props` | object | No | Private configuration for provider-backed `Integration`, MCP, and SQL database artifacts. The legacy alias `private_config` is also accepted on create. |
| `scopes` | object[] | No | Artifact visibility rules. Each item has `scope_type` (`organization` or `project`), `scope_id`, optional `enabled`, optional `ws_auto_select`, and optional `delete` (defaults to `false`). |
| `scopes[].scope_type` | string | Yes | `organization` or `project`. |
| `scopes[].scope_id` | string | Yes | Organization or project identifier matching `scope_type`. |
| `scopes[].enabled` | boolean | No | Whether the artifact is visible in this scope. Defaults to `true` for a new scope. |
| `scopes[].ws_auto_select` | boolean | No | Whether Workspace automatically selects it in this scope. Defaults to `false` for a new scope. |
| `scopes[].delete` | boolean | No | Remove the matching scope. Defaults to `false`; normally used by update and scope operations. |
| `file_data` | file | Conditional | Multipart-only file binary. A successful `Document` or `Skill` create requires either this field or JSON `content`. |
</Accordion>

When `scopes` is omitted, a project artifact receives its project scope and an organization artifact receives its organization scope. An organization artifact cannot be created with project scopes; add those later with the scope operation.

### Document artifacts

Document artifacts hold content, links reference existing artifacts, and folders organize artifacts inside an organization or project.

<Tabs>
  <Tab title="Document">
<Accordion title="props body">
| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `file_name` | string | Yes | Original file name. |
| `content_type` | string | Yes | MIME type of `file_data`. |
| `content_length` | integer \| null | No | File size in bytes. It must be present and match the uploaded bytes for successful document processing; if omitted, the artifact is created in `Error` state with `ingest_status: NotApplicable`. |
| `metadata` | object | No | Provider-specific metadata for integration-backed documents. |
| `original_path` | string \| null | No | Original mounted path when the artifact was promoted from a thread. |
</Accordion>

```bash
printf 'Q1 support summary.\n' > q1-support-summary.txt

curl -X POST "https://{BASE_URL}/api/v1/app/artifact" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -F 'project_id={projectID}' \
  -F 'type=Document' \
  -F 'name=Q1 Support Summary' \
  -F 'props={
    "content_type":"text/plain",
    "file_name":"q1-support-summary.txt",
    "content_length":20
  };type=application/json' \
  -F 'file_data=@./q1-support-summary.txt;type=text/plain'
```

<Accordion title="Example response">
```json

  "id": "artifact_doc_q1",

    "file_name": "q1-support-summary.txt",
```

### Other artifacts

Other artifacts provide tools, provider connections, and reusable skills. `private_props` is used by **MCP**, **SQL database**, and provider-backed `Integration` artifacts. For `Integration` request shapes, see the [Confluence](/en/developer-manual/build-with-zylon/workspace-api/integrations/confluence), [SharePoint](/en/developer-manual/build-with-zylon/workspace-api/integrations/sharepoint), [Filesystem](/en/developer-manual/build-with-zylon/workspace-api/integrations/filesystem), and [Claromentis](/en/developer-manual/build-with-zylon/workspace-api/integrations/claromentis) guides.

<Tabs>

<Accordion title="props body">
| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `schemas` | string[] \| null | No | Database schemas to expose. |

| `ssl` | boolean \| null | No | Whether the database connection uses SSL. Runtime default: `true`. |

## Working with artifacts

### List artifacts

Use `GET /api/v1/app/artifact`. With `x-org`, omit `organization_id`; use `project_id` to narrow the result to one project or omit it to list the artifacts visible across the selected organization. Without `x-org`, Operator and SuperAdmin callers can select an organization with `organization_id`, or omit both ownership parameters for a cross-organization list of accessible artifacts.

| `ingest_status` | string | No | Comma-separated values from `NotApplicable`, `NotStarted`, `Processing`, `Parsing`, `Storing`, `Done`, and `Error`. Defaults to all statuses. |

### Validate create and update requests

Validate a create payload with `POST /api/v1/app/artifact/validate`. It accepts the same JSON or multipart body as create. Validate a JSON update payload with `POST /api/v1/app/artifact/{artifactID}/validate`; file replacement multipart bodies are validated when submitted to the update operation itself. Validation does not persist the change. These validation operations currently support `Skill` and `SqlDatabase` artifacts.

```bash
curl -X POST "https://{BASE_URL}/api/v1/app/artifact/validate" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "{projectID}",
    "type": "SqlDatabase",
    "name": "Sales database",
    "props": {
      "ssl": true,
      "enable_tables": true
    },
    "private_props": {
      "connection_string": "{DATABASE_CONNECTION_STRING}"
    }
  }'
```

<Accordion title="Example response">
```json
{
  "valid": true,
  "errors": [],
  "warnings": []
}
```
</Accordion>

The response contains `valid`, `errors`, and `warnings`, plus optional `data`. Each error or warning contains `type`, `message`, and optional `params`. Skill validation can return parsed `name` and `description` values in `data`.

To validate an update against the artifact's stored configuration:

```bash
curl -X POST "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/validate" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Sales database (validated)"
  }'
```

## Errors and edge cases

- **Artifact error codes**: the `error` field maps to ingest failures:

| `error` value | Meaning |
| --- | --- |
| `InvalidExtension` | File extension is not supported. |
| `MismatchedType` | File type does not match the declared artifact type. |
| `Malformed` | File is corrupt or unreadable. |
| `Encrypted` | File is password‑protected. |
| `ParsingFailure` | Extractor failed to parse the file. |
| `MaxNodes` | Document is too large/complex for parsing. |
| `NoValidFile` | No valid file was found in the upload. |
| `NoValidNodes` | No parseable content was extracted. |
| `InternalError` | Ingest pipeline failed unexpectedly. |
| `Unknown` | Unclassified ingest failure. |

If `ingest_status` is `Error`, fix the source file and retry or replace the artifact. For integration artifacts, correct the source and sync again.
- **Warnings**: `ingest_warnings` can include values like `BigSize`, `UnprocessableContent`, or `NoContent` to indicate non‑fatal issues.
- **400**: required ownership is missing or invalid, such as sending `project_id` without selecting an organization, or a synchronization is already in progress.
- **401/403**: token missing, insufficient permissions, or `organization_id` combined with `x-org`.
- **404**: artifact, organization, or project not found. A retry payload with ownership that differs from the original artifact is also rejected as not found.
- For files larger than 250 MB, the backend retains only the artifact record with an `UnprocessableContent` warning; it does not store the uploaded bytes or start ingestion.
