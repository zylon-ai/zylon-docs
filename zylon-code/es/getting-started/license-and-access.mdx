Zylon Code necesita una licencia vigente de la instalación de Zylon de tu organización que incluya **Zylon Code**. La gestiona el administrador o tu contacto de Zylon. En Desktop introduces el dominio de la instalación; esta configuración no pide subir un archivo de licencia ni escribir una clave de activación.

## Tres comprobaciones distintas

| Requisito | Qué permite |
| --- | --- |
| Licencia vigente que incluya Zylon Code | Crear agentes, enviar peticiones al modelo y ejecutar herramientas en la aplicación. |
| Clave de API del gateway y acceso de la cuenta | Utilizar los modelos con los permisos y las cuotas que correspondan. |
| Servicio de modelos accesible | Completar las peticiones al modelo durante la tarea. |

Elegir otro proveedor o ampliar los permisos no evita el requisito de licencia de Zylon Code. [Conectar con Zylon](/zylon-code/es/getting-started/connect-to-zylon) explica cómo configurar primero el dominio y después la clave.

## Qué comprueba Desktop

La aplicación consulta la licencia pública del dominio configurado. Esa petición no envía tu token de desarrollador. La instalación debe indicar que Zylon Code está habilitado y que la licencia no ha caducado. Si falta esa habilitación, no hay licencia o está caducada, se bloquea el uso aunque hayas podido descargar la aplicación.

Para el administrador, los campos relevantes son `metadata.zylon_code_enabled` y `valid_until` en `GET /api/v1/license`. La licencia también puede incluir un número de puestos de Zylon Code; esta comprobación de Desktop no los asigna ni los cuenta. Confirma el acceso contratado con el administrador: esos datos no son una pantalla de activación por dispositivo.

## Si Zylon no está disponible temporalmente

Desktop intenta comprobar la licencia al arrancar y renueva la autorización cuando hace falta. Si ya hubo una comprobación correcta para el mismo dominio, puede utilizarla temporalmente ante un fallo de red o del servidor. El periodo predeterminado es de cinco días desde esa comprobación, sin superar la caducidad de la licencia; el administrador puede configurar otro periodo admitido.

Este margen no proporciona conexión a los modelos. La tarea sigue necesitando acceso al servicio del modelo que utilice. La primera configuración y la conexión a otro dominio requieren una comprobación correcta.

Una denegación explícita, una respuesta inválida, una comprobación caducada, otro dominio o un problema de certificado no permiten utilizar ese margen. Si falta la autorización, el diálogo del dominio impide trabajar hasta resolverlo. Cambiar la clave de API no arregla una licencia caducada o sin Zylon Code.

## Resuelve un problema de licencia

Revisa el dominio en **Ajustes → General** o en la bienvenida que bloquea la aplicación. Debe ser una dirección como `https://zylon.example`, sin `/api/gpt`. Confirma con el administrador el acceso de red y cualquier certificado privado. Si el dominio es correcto, pídele que compruebe que la licencia siga vigente e incluya Zylon Code, o contacta con ventas de Zylon.

Conserva los archivos del proyecto y los datos de la aplicación mientras investigas. Reinstalar o borrar conversaciones no renueva la licencia de una instalación. [Problemas de inicio y modelos](/zylon-code/es/troubleshooting/setup-and-models) distingue los fallos de licencia de los problemas de modelos y tokens.
