Minimal uses a fixed system prompt, a persistent platform shell, image reading and history compaction. It does not automatically load project instructions, skills, integrated planning, goals or ordinary delegation. Optional global plugins can still add tools.

Enable **Settings → General → Developer view** if Minimal is absent from the new-task picker. Select it before the first message.

## Try a bounded task

> Run the project's already-installed parser tests. Identify the failing behavior and report the cause with the relevant output. Do not edit files or install packages.

Inspect the shell commands and actual output. The shell can read files, write them and execute scripts when permissions allow it. A smaller tool catalog does not make the task automatically safer.

The persistent shell retains state between calls. Image reading requires a model configured to accept images. Automatic compaction and the idle-session `/compact` command summarize older context; review the original recorded activity when the detail matters.

## Provide project rules explicitly

Minimal does not use the standard instruction loader for `AGENTS.md`. Put the relevant rules in your task or choose [Standard](/zylon-code/modes/standard). Compaction does not add missing project conventions.

## Compare fairly

Keep the model, permissions, prompt, enabled global plugins and starting files identical across runs. A new conversation does not reset files. For normal work involving skills, planning or local subagents, start with Standard; use a [custom mode](/zylon-code/customization/custom-modes) when you need a different composition.
