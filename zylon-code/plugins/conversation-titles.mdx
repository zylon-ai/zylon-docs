The Conversation-following titles plugin keeps generated chat titles useful as a task develops. The normal title provider uses the first prompt. This experimental alternative can revise the title after later messages change or expand the main topic, making the chat easier to recognize in the sidebar.

It changes the title, not the agent's task or project files. It does not add tools or summarize the complete tool history for the main agent.

## Enable it

Open **Plugins → Experimental plugins → More** and enable **Conversation-following titles**. It starts disabled. The title provider then applies to existing and new conversations as eligible messages arrive.

## Example: a task grows beyond its original question

You start with:

> Investigate why an empty search shows an error. Do not edit yet.

The investigation finds a shared problem, so you continue:

> The category filter uses the same validation. Extend the review to both paths and report the common cause before proposing a fix.

The generated title can change to reflect that wider task. It should remain unchanged if the old title still fits. A “thanks”, a request to continue or a small clarification should not require a new title. These are instructions to the title model, so the wording is not guaranteed to stay identical.

Automatic updates preserve titles you set manually. Use the chat's **Rename** action when you want a specific stable name.

## Check behavior and usage

Title generation uses separate model requests based on your eligible messages. It can consume tokens and fail independently of the main task. A failed request or an input that exceeds its configured size retains the previous title; an unchanged title does not mean the main agent stopped.

Disable the plugin to restore the first-prompt title provider. Existing conversation titles and work remain. Use [Session search](/zylon-code/plugins/session-search) when you need the agent to retrieve an earlier decision rather than rename a chat.
