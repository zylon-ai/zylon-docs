PTC means Programmatic Tool Calling. The agent uses `run_code` to write a TypeScript program that calls tools through a generated SDK. You describe the task; you do not need to write the program yourself.

Choose PTC before starting the conversation. If it is missing, enable **Settings → General → Developer view**.

## Example

> Check JSON files in configs/ against schema.json. Save a CSV with one row per issue. Include unreadable files and continue checking the rest. Leave the originals unchanged.

The program can loop over files, catch individual failures and aggregate results. Tool outputs first reach that program; the model receives what it prints or returns, with supported images handled separately. Nested calls are still recorded and governed by tool permissions.

## Inspect the result

Expand the program and nested tool activity. Check whether failed files were included rather than silently skipped. Open the CSV and compare a few rows with the inputs. Request bounded output instead of asking the program to print every intermediate result.

## Limits

PTC has skills, instructions, goals, planning, delegation and compaction. Its built-in preset disables the workflow tool. It does not promise lower token use or better performance than Standard: results depend on the task and program. Tool availability, filesystem access and approval policy still apply.

Choose [Standard](/zylon-code/modes/standard) for direct tools or read [workflows](/zylon-code/tools/workflows) for the separate reusable workflow feature.
