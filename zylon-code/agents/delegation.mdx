Standard, PTC and Creator can delegate work to child agents. A fresh child receives a task prompt; a forked child begins with inherited context. Neither automatically receives an isolated checkout.

## Give a bounded task

> Delegate a read-only review of the parser tests to a separate agent. Keep the implementation investigation in this chat. Wait for its findings and combine them with your own.

Name scope, expected output and edit restrictions. Give fresh children the paths and facts they need. Avoid asking two agents to change the same files independently.

## Follow the work

The main conversation header shows its agents, including agents they have created. Open a child conversation in the main view or sidebar to read its tools and replies. Some agents accept follow-ups and can be stopped; others finish after one assigned task. Follow-up messages can queue while a continuable child is busy.

Mentioning an agent's name in ordinary text is not itself a routing command. Ask the parent to send the follow-up through its agent control or use the child conversation's supported input.

## Verify the outcome

Read the child's final result and relevant tool evidence. The parent should report failed or cancelled children rather than treating their absence as success. If the parent is unavailable after recovery, some controls may be unavailable too.

Configure [models and limits](/zylon-code/agents/models-and-limits). [Agent Teams](/zylon-code/plugins/agent-teams) provides a different roster/task-board collaboration feature.
