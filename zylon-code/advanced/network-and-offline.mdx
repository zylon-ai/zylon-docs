An internal model gateway can keep model requests on an approved network. Tools, account providers, plugins and project commands may still contact other services. Prepare and test the actual Desktop installation in your organization's network.

## License verification

Startup checks the saved Zylon domain's license. After a successful check, a temporary same-domain receipt can allow use during a network outage or server failure: five days by default, never beyond license expiry. Your administrator can configure a different allowed grace period. A denied or invalid license, a certificate failure or an expired receipt blocks access. This is temporary license tolerance, not a promise of offline model availability.

First setup and a different domain need a successful verification. Keep the deployment's license endpoint and model endpoint reachable over your approved network. A local model does not remove Zylon Code's deployment-license requirement.

## Private certificates

The domain form in **Settings → General** can request confirmation for a valid certificate from an untrusted issuer. Compare its origin, SHA-256 fingerprint, issuer and dates with your administrator before accepting. Approval applies to that domain and certificate; a changed certificate needs confirmation again. Forgetting approval also clears the cached authorization. [Custom model providers](/zylon-code/models/providers) have their own discovery confirmation.

For an organization-wide trust setup, ask the administrator to prepare the application's certificate store or approved launch environment. Keep hostname and certificate verification enabled. Opening the deployment in your browser does not confirm that the application's connection uses the same trust settings.

## Proxies and dependencies

The local runtime reads `HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY` and `NO_PROXY` at startup. Its proxy path supports HTTP proxies and host/domain exclusions, with direct loopback access; SOCKS and CIDR exclusions are not supported through that path. An approved launch environment can add trust through `NODE_EXTRA_CA_CERTS`. Restart after changing that environment.

Commands and local MCP processes can inherit proxy variables. Do not print their values in shared diagnostics. Optional runtime downloads, model services, document tools and plugin sources must be reachable locally or through approved internal services.

Test startup, a model request, tool use and reopening a conversation in the intended network. [Privacy](/zylon-code/configuration/privacy) describes potential destinations; [Availability](/zylon-code/reference/availability) lists optional prerequisites.
