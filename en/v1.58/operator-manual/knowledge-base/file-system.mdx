---
title: "Samba File System"
description: "Connect an existing SMB share to Zylon and troubleshoot paths, credentials, network access, and security compatibility."
---

The **File System** connector reads files from an existing Samba/SMB server. The Zylon backend connects directly to that server; the user's browser does not mount the share.

An operator configures the server and share for the Zylon installation. Users then enter their Samba credentials in Workspace and choose which files or folders to import. Follow the [user guide](/en/v1.58/user-manual/connectors/file-system) for those steps.

## Before you start

Have the following ready:

- A Samba hostname or IP address and its SMB TCP port, normally `445`.
- The **exported share name**, as shown in the Samba server's configuration or share list.
- A Samba account allowed to connect to the share, list and traverse its folders, and read the required files. Both Samba share permissions and underlying filesystem permissions must allow access.
- DNS resolution and network access **from the Zylon backend pods** to the Samba server. Access from your laptop or from a shell on the Samba server does not establish this.
- A server compatible with the connector's [protocol and security requirements](#protocol-and-security-compatibility).

## Distinguish the server, share, and subfolder

For this example, a document is available at:

```text
smb://files.example.com:445/zylon-samba/Departments/HR policies/handbook.pdf
```

| Part | Example | Where to use it |
| --- | --- | --- |
| Server | `files.example.com` | `external.samba.host` |
| TCP port | `445` | `external.samba.port` |
| Exported share | `zylon-samba` | `external.samba.name` |
| Folder inside the share | `Departments/HR policies` | Select it in the Workspace folder picker |
| File | `handbook.pdf` | Select it, or import its parent folder |

**`name` means the exported SMB share name.** For a Samba server, this is the section name such as `[zylon-samba]` in `smb.conf`. It is not the local path configured by that share's `path` setting, a subfolder, or a name for the connector in Zylon.

For the example above, use `name: "zylon-samba"`. Do not use `/srv/documents`, `Departments/HR policies`, `zylon-samba/Departments/HR policies`, a UNC path, or the complete `smb://` URL.

The connection root is configured for the installation, not in the user's login form. There is no separate initial-subfolder setting. To expose only a subtree as the connection root, have the Samba administrator export it as its own share and configure that share name. Review the effect on existing connectors before changing the installation's server or share.

## Configure the connection

For a CLI-managed installation, merge these settings into `/etc/zylon/zylon-conf.yaml`. For a Helm-managed installation, use the same keys in your Zylon Helm values file.

```yaml
integration:
  filesystem:
    enabled: true
    protocol: "samba"

external:
  samba:
    host: "files.example.com"
    port: 445
    name: "zylon-samba"
```

If `integration` or `external` already exists, edit its existing mapping. **Do not append duplicate top-level keys** or replace unrelated settings.

| Setting | Meaning | Default / required value |
| --- | --- | --- |
| `integration.filesystem.enabled` | Enables File System in Zylon. | Default: `false`; set to `true`. |
| `integration.filesystem.protocol` | Selects the chart's Samba configuration. | Set exactly to `"samba"`. |
| `external.samba.host` | Hostname or IP reachable from the backend. | Required; no URL scheme, share, path, or port. |
| `external.samba.port` | SMB TCP port. | Default: `445`. |
| `external.samba.name` | Exported SMB share name. | Set explicitly to your share; chart default: `"zylon-samba"`. |

<Warning>
  The configuration value is `protocol: "samba"`, even though the connection URL uses `smb://`. Setting `protocol: "smb"` does not configure the backend's host, protocol, or share.
</Warning>

Enter the external server's credentials in the Workspace connector form. Adding `username` and `password` under `external.samba` does not supply credentials for this connection.

### Apply the configuration

For CLI-managed installations, run:

```bash
sudo zylon-cli sync
```

For Helm-managed installations, apply the updated values through your normal Helm upgrade procedure, retaining the intended chart version and existing release settings.

The chart translates these settings into the following backend runtime variables. These are useful for checking the effective deployment, not additional YAML keys to add:

| Runtime variable | Expected value for this example |
| --- | --- |
| `INTEGRATION_FILESYSTEM_ENABLED` | `true` |
| `INTEGRATION_FILESYSTEM_PROTOCOL` | `smb` |
| `INTEGRATION_FILESYSTEM_HOST` | `files.example.com:445` |
| `INTEGRATION_FILESYSTEM_ROOT` | `zylon-samba` |

## Check connectivity and permissions

Run checks from the backend pod network, or have your Kubernetes administrator use an approved diagnostic environment with equivalent DNS, routing, and network policies. A successful check on the Kubernetes host alone may not prove pod connectivity. The commands below require the corresponding diagnostic tools; they do not require a filesystem mount.

```bash
getent hosts files.example.com
nc -vz files.example.com 445
smbclient '//files.example.com/zylon-samba' -p 445 -U zylon
```

Replace the hostname, share, port, and example username `zylon` with your own. Let `smbclient` prompt for the password; do not include it in the command.

At the `smbclient` prompt, check the target folder:

```text
ls
cd "Departments/HR policies"
ls
quit
```

Expected result: the account can connect to the share and list the target folder. Also confirm it can read the files intended for import. Listing all available shares alone does not prove access to a particular folder.

A successful `smbclient` test establishes access with that client, not full compatibility with Zylon. Modern SMB clients can support encryption or authentication methods that Zylon's connector does not.

## Protocol and security compatibility

- The connector is configured to negotiate **SMB 2.1 through SMB 3.1.1**. SMB1 and SMB 2.0.2 are outside that range.
- **Mandatory SMB3 transport encryption is not supported by the current connector client.** Check the server's global and share-level encryption policy, including `server smb encrypt` (called `smb encrypt` in some Samba versions). Requiring encryption can prevent access despite correct credentials. See the [Samba encryption reference](https://www.samba.org/samba/docs/4.21/man-html/smb.conf.5.html#SERVERSMBENCRYPT).
- SMB signing and SMB encryption are different requirements. Report both policies when investigating compatibility; a signing requirement alone does not establish that encryption is required.
- This connector uses direct SMB. It does not offer TLS certificate, custom CA, client-certificate, or SMB-over-QUIC configuration. HTTPS certificates for Zylon or the NAS web interface do not configure this connection.
- FTP, FTPS, SFTP, NFS, and WebDAV are not protocols for this connector. A certificate-protected FTP endpoint is not an SMB share.
- There is no separate domain/workgroup setting in this connection configuration. If access depends on a specific domain, Kerberos, or DFS referrals, confirm compatibility with Zylon support before rollout; DFS referral resolution is disabled in the current client.

If your security policy requires unsupported encryption or transport, contact Zylon support to review compatibility. Do not treat installing a certificate as a way to add SMB encryption support or weaken the server's policy to make the example work.

## Enter credentials and select content

In the project's Knowledge Base, choose **Add files → From File System**. Enter the Samba **Username** and **Password**, then browse the configured share and select your content.

A local Samba username such as `zylon` is valid input: **the username does not have to be an email address**. Use the Samba account's password, which may differ from the user's Zylon login password. The form does not ask users to configure the host, share, or folder path.

Credentials belong to the connector and are reused for its reads and syncs. They are not a separate SMB login for every person viewing imported content. Everyone with access to the project can access the content imported into its Knowledge Base, independently of the original SMB permissions.

See the [File System user guide](/en/v1.58/user-manual/connectors/file-system) for importing and updating content, and [scheduled synchronization](/en/v1.58/operator-manual/configuration/cron-tasks/sync) for optional automatic updates.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| File System is absent from Add files | Confirm the integration is enabled and the updated deployment configuration has been applied. |
| The form reports invalid user or password | This message can also result from a connection failure. Check backend DNS, port, exact share name, actual Samba credentials, permissions, and security compatibility before assuming the password is wrong. |
| The account works on the server or a laptop, but not in Zylon | Repeat the access check from the backend network with the same account. Local filesystem access is different from SMB access. Check domain/authentication requirements and encryption policy. |
| A known folder is missing or appears empty | Confirm the correct share and access to every parent folder. Check whether it is marked hidden: the connector filters hidden entries. Some SMB listing errors can leave folders without visible children; inspect backend and Samba diagnostics. |
| `Server requires encryption, not yet supported.` appears in backend diagnostics | The server requires SMB encryption that the current client cannot provide. Review compatibility with Zylon support. |
| The wrong root opens | Check `external.samba.host` and `external.samba.name`. Select subfolders in Workspace rather than adding them to `name`. |

For support, provide the Zylon version, timestamp of the failed attempt, non-secret connection settings, whether direct SMB works from the backend network, and the applicable server policies. Collect the relevant backend and Samba error messages using the [diagnostics guide](/en/v1.58/operator-manual/troubleshooting/exporting-logs). Remove passwords, tokens, and sensitive paths or filenames before sharing diagnostics.
