A conversation keeps prompts, model replies and tool activity for one task. Select its project and open the chat from the sidebar to continue. Renaming changes its display title; pinning keeps it prominent. Archiving changes visibility rather than deleting the project files.

## While the agent works

- **Stop** requests interruption. Actions already completed are not undone.
- **Queue** saves a follow-up for later processing.
- **Steer** delivers a new instruction during the running task.

The busy-send preference determines the normal Enter behavior. Inspect the active control instead of assuming every send interrupts the agent. Queued messages have their own edit/remove/steer controls once the application acknowledges them; a “Sending…” entry has not yet become an actionable queue item.

Example steering message:

> Keep the current investigation, but do not install dependencies. Use the existing tests and report any unavailable checks.

## Fork or resume

Use **Fork** to start a related conversation with inherited history. This creates conversation history, not an isolated Git worktree or a copy of your files. Both chats can affect the same checkout. Use a separately prepared folder if you need filesystem isolation.

Reloading restores recorded history. It does not reverse changes or necessarily restore external browser state. A failed or interrupted turn can be followed by a precise recovery request after you inspect the files and running jobs.

For long tasks, use [goals](/zylon-code/everyday-use/goals-and-task-lists) and [compaction](/zylon-code/everyday-use/long-conversations). Child-agent controls are documented under [delegation](/zylon-code/agents/delegation).
