title: "Artefactos"
description: "Artefactos de Workspace para documentos, flujos y conectores."
---

Un artefacto es una pieza de información **o herramienta** que le entregas a Zylon para usarla como contexto en consultas y operaciones. La Workspace API agrupa los artefactos en **documentos**, **documentos IA** y **otros artefactos**.

## Requisitos previos

- Un token de API. Ver [Gestión de tokens de Workspace](/es/developer-manual/get-started/token-management).
- El nombre de host de Zylon (sustituye `{BASE_URL}` en los ejemplos).

## Artefactos

| Categoría | Incluye | Cuándo usar |
| --- | --- | --- |
| **Artefactos de documento** | Documentos, carpetas, enlaces | Guardar u organizar contenido en un proyecto. |
| **Documentos IA** | `Summary`, composición, extracción | Ejecutar flujos sobre artefactos para producir resultados. |
| **Otros artefactos** | Servidores MCP, bases de datos SQL, integraciones, skills | Conectar herramientas, fuentes externas o instrucciones reutilizables. |

### Campos de petición de artefacto

Usa `POST /api/v1/app/artifact` para crear cualquier tipo de artefacto. El cuerpo indica la organización o el proyecto propietario e incluye metadatos compartidos y un objeto `props` específico del tipo.

Cuando envías la cabecera `x-org`, omite `organization_id`: la organización se obtiene de la cabecera. Usa `project_id` para crear el artefacto dentro de un proyecto u omítelo para crear un artefacto de organización; esto último requiere el rol `AppAdmin` o superior. Sin `x-org`, los operadores y superadministradores deben enviar `organization_id`; si también envían `project_id`, este debe pertenecer a esa organización. Los artefactos `Link` siempre requieren `project_id`.

<Accordion title="Campos de petición de artefacto">
| Campo | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `organization_id` | string | Condicional | Organización propietaria. Omítelo al usar `x-org`; sin esa cabecera, solo pueden enviarlo operadores y superadministradores. |
| `project_id` | string \| null | No | Proyecto propietario. Omítelo o usa `null` para crear un artefacto de organización. Es obligatorio para `Link`. |
| `type` | string | Sí | Tipo de artefacto. Los tipos expuestos incluyen `Document`, `Folder`, `Link`, `Integration`, `Skill`, `Summary`, `Composition`, `BulkQA`, `ReadAndExtract`, `Analysis`, `SmartDoc`, `SqlDatabase` y `McpServer`. |
| `name` | string | Sí | Nombre visible del artefacto. |
| `props` | object | Sí | Configuración específica del tipo. También se acepta el alias legado `config`. |
| `source` | string | No | Fuente del artefacto. Los valores de producción son `User`, `SharePoint`, `GoogleDrive`, `Confluence`, `ConfluenceLocalLegacy`, `Claromentis`, `FileSystem`, `Assistant` y `System`. Por defecto es `User`. |
| `description` | string | No | Descripción legible. |
| `parent_id` | string | No | Artefacto padre para artefactos de árbol, como documentos, carpetas y enlaces. No lo uses para artefactos MCP o de base de datos. |
| `integration_id` | string | No | ID de integración para artefactos respaldados por integraciones. También se acepta `integration_artifact_id`. |
| `external_url` | string | No | URL externa para enlaces o artefactos respaldados por conectores. |
| `content` | string | Condicional | Contenido codificado en Base64 al crear mediante JSON. Para crear correctamente un `Document` o `Skill`, envía este campo o `file_data` multipart. |
| `keep_file_after_ingestion` | boolean | No | Indica si se conserva el archivo subido tras la ingesta. Por defecto es `true`. |
| `interaction_id` | string | No | Interacción que produjo el artefacto, si aplica. |
| `private_props` | object | No | Configuración privada para artefactos `Integration` respaldados por proveedores, MCP y SQL database. También se acepta el alias legado `private_config` al crear. |
| `scopes` | object[] | No | Alcances iniciales del artefacto. |
| `scopes[].scope_type` | string | Sí | `organization` o `project`. |
| `scopes[].scope_id` | string | Sí | ID de la organización o el proyecto indicado por `scope_type`. |
| `scopes[].enabled` | boolean | No | Indica si el artefacto está visible en este alcance. Por defecto es `true` al crear un alcance. |
| `scopes[].ws_auto_select` | boolean | No | Permite que Workspace seleccione automáticamente el artefacto en este alcance. Por defecto es `false` al crear un alcance. |
| `scopes[].delete` | boolean | No | Elimina el alcance coincidente. Por defecto es `false`; se usa normalmente al actualizar o modificar alcances. |
| `file_data` | file | Condicional | Binario multipart. Para crear correctamente un `Document` o `Skill`, envía este campo o `content` en JSON. |
</Accordion>

Si omites `scopes`, un artefacto de proyecto recibe su alcance de proyecto y un artefacto de organización recibe su alcance de organización. No puedes crear un artefacto de organización con alcances de proyecto; añádelos después con la operación de alcance.

### Artefactos de documento

Los documentos contienen contenido, los enlaces referencian artefactos existentes y las carpetas organizan artefactos dentro de una organización o un proyecto.

<Tabs>
  <Tab title="Document">
<Accordion title="props body">
| Campo | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `file_name` | string | Sí | Nombre original del archivo. |
| `content_type` | string | Sí | MIME type de `file_data`. |
| `content_length` | integer \| null | No | Tamaño del archivo en bytes. Debe estar presente y coincidir con los bytes subidos para procesar correctamente el documento; si se omite, el artefacto se crea en estado `Error` con `ingest_status: NotApplicable`. |
| `metadata` | object | No | Metadatos del proveedor para documentos respaldados por integraciones. |
| `original_path` | string \| null | No | Ruta montada original cuando el artefacto se promocionó desde un thread. |
</Accordion>

```bash
printf 'Q1 support summary.\n' > q1-support-summary.txt

curl -X POST "https://{BASE_URL}/api/v1/app/artifact" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -F 'project_id={projectID}' \
  -F 'type=Document' \
  -F 'name=Q1 Support Summary' \
  -F 'props={
    "content_type":"text/plain",
    "file_name":"q1-support-summary.txt",
    "content_length":20
  };type=application/json' \
  -F 'file_data=@./q1-support-summary.txt;type=text/plain'
```

### Documentos IA

Los documentos IA ejecutan un flujo de trabajo de Zylon sobre uno o más artefactos para producir un resultado estructurado.

<Tabs>
  <Tab title="Summary">
<Accordion title="props body">
| Campo | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `artifact_ids` | string[] | Sí | Artefactos de entrada a resumir. |
| `style` | string | Sí | `Expert`, `Neutral` o `Simple`. Valores obsoletos aún pueden decodificar, pero no deben usarse. |
| `detail` | string | Sí | `KeyPoints`, `ShortPieces` o `LongPieces`. Valores obsoletos aún pueden decodificar, pero no deben usarse. |

### Otros artefactos

Los otros artefactos proporcionan herramientas, conexiones con proveedores y skills reutilizables. `private_props` se usa en artefactos **MCP**, **SqlDatabase** y `Integration` respaldados por proveedores. Consulta las formas de petición de `Integration` en las guías de [Confluence](/es/developer-manual/build-with-zylon/workspace-api/integrations/confluence), [SharePoint](/es/developer-manual/build-with-zylon/workspace-api/integrations/sharepoint), [Filesystem](/es/developer-manual/build-with-zylon/workspace-api/integrations/filesystem) y [Claromentis](/es/developer-manual/build-with-zylon/workspace-api/integrations/claromentis).

<Tabs>
  <Tab title="SqlDatabase">
<Accordion title="props body">
| Campo | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `schemas` | string[] \| null | No | Esquemas de base de datos a exponer. |
| `tables` | string[] \| null | No | Tablas de base de datos a exponer. |
| `ssl` | boolean \| null | No | Indica si la conexión usa SSL. Valor efectivo por defecto: `true`. |
| `enable_tables` | boolean \| null | No | Habilita descubrimiento/uso de tablas. Valor efectivo por defecto: `true`. |
| `enable_views` | boolean \| null | No | Habilita descubrimiento/uso de vistas. Valor efectivo por defecto: `true`. |
| `enable_procedures` | boolean \| null | No | Habilita procedimientos almacenados. Valor efectivo por defecto: `false`. |
| `enable_functions` | boolean \| null | No | Habilita funciones. Valor efectivo por defecto: `false`. |
| `private_props.connection_string` | string | Sí | Cadena de conexión. En ejemplos y logs, enmascara secretos. |
</Accordion>

```bash
curl -X POST "https://{BASE_URL}/api/v1/app/artifact" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "{projectID}",
    "type": "SqlDatabase",
    "source": "User",
    "name": "Sales database",
    "description": "Read-only reporting database.",
    "props": {
      "schemas": ["public", "analytics"],
      "tables": ["orders", "customers"],
      "ssl": true,
      "enable_tables": true,
      "enable_views": true,
      "enable_procedures": false,
      "enable_functions": false
    },
    "private_props": {
      "connection_string": "postgresql://readonly:***@db.example.com:5432/sales"
    }
  }'
```

<Accordion title="Ejemplo de respuesta">

## Trabajar con artefactos

### Listar artefactos

Con `x-org`, el listado queda limitado a esa organización y no admite `organization_id`. Sin `x-org`, los operadores y superadministradores pueden seleccionar una organización con `organization_id`; si lo omiten, el backend busca en las organizaciones a las que tienen acceso. `project_id` requiere una organización seleccionada.

<Accordion title="Parametros del endpoint">
| Parámetro de consulta | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `organization_id` | string | Condicional | Organización que se consulta. Omítelo al usar `x-org`; sin esa cabecera, solo pueden enviarlo operadores y superadministradores. |
| `project_id` | string | No | Limita el listado a un proyecto. Si se envía junto con `organization_id`, debe pertenecer a esa organización. |
| `state` | string | No | Valores separados por comas de `Initializing`, `Processing`, `Draft`, `Deleted`, `Published`, `Unavailable` y `Error`. Por defecto es `Published,Processing`. |
| `source` | string | No | Orígenes separados por comas, como `User`, `SharePoint`, `Confluence`, `Claromentis` o `FileSystem`. |
| `ingest_status` | string | No | Valores separados por comas de `NotApplicable`, `NotStarted`, `Processing`, `Parsing`, `Storing`, `Done` y `Error`. Por defecto incluye todos. |
| `type` | string | No | Tipos de artefacto separados por comas. |
| `scopes` | JSON array | No | Filtros de alcance. Cada elemento requiere `scope_type`, `scope_id` y el booleano `enabled`. `ws_auto_select` es opcional y vale `false` por defecto, pero no interviene en el filtrado. |
| `parent_id` | string | No | Limita los resultados a hijos directos de un artefacto padre. |
| `include_descendants` | boolean | No | Incluye todo el subárbol bajo `parent_id`; si no hay padre, incluye todos los descendientes del alcance seleccionado. |
| `filter_by_text` | string | No | Búsqueda de texto sobre nombres de artefactos. |
| `keep_ancestors` | boolean | No | Incluye los ancestros de los artefactos que coinciden con la consulta completa. |
| `resolve_links` | boolean | No | Resuelve artefactos Link en listados de proyecto. Sin `parent_id`, solo añade sus descendientes cuando `include_descendants=true`; con un Link como padre, devuelve sus hijos directos o todo su subárbol según `include_descendants`. |
| `sub_type` | string | No | Tipos separados por comas para filtrar destinos de enlaces mediante `props.original_artifact_type`; también se conservan los artefactos sin esa propiedad. |

| `page_size` | integer | No | Elementos por página cuando se usa `page`. Por defecto es `50`; la paginación por cursor usa `first` o `last`. |
| `page_order` | string | No | Orden por ID para paginación absoluta: `ASC` o `DESC`. Por defecto es `ASC`. |
| `after`, `before` | string | No | Cursores de ID de artefacto para paginación hacia delante o hacia atrás. |
| `first`, `last` | integer | No | Límite positivo de resultados después o antes de un cursor. |

### Validar antes de crear o actualizar

La validación está implementada para artefactos `Skill` y `SqlDatabase`. Usa `POST /api/v1/app/artifact/validate` con el mismo cuerpo de creación que enviarías a `POST /api/v1/app/artifact`. Para validar la actualización de uno de esos artefactos, usa `POST /api/v1/app/artifact/{artifactID}/validate` con el mismo cuerpo JSON que enviarías a `PUT /api/v1/app/artifact/{artifactID}`. Ninguna de las dos operaciones guarda cambios.

```bash
curl -X POST "https://{BASE_URL}/api/v1/app/artifact/validate" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "{projectID}",
    "type": "SqlDatabase",
    "name": "Sales database",
    "props": {
      "ssl": true,
      "enable_tables": true
    },
    "private_props": {
      "connection_string": "{DATABASE_CONNECTION_STRING}"
    }
  }'
```

```bash
curl -X POST "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/validate" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Type: application/json" \
  -d '{
    "props": {
      "ssl": true,
      "enable_tables": true
    },
    "private_props": {
      "connection_string": "{DATABASE_CONNECTION_STRING}"
    }
  }'
```

Ambas rutas devuelven el mismo modelo de validación:

```json
{
  "valid": true,
  "errors": [],
  "warnings": []
}
```

La respuesta contiene `valid`, `errors` y `warnings`, además del campo opcional `data`. Cada error o advertencia contiene `type`, `message` y, opcionalmente, `params`. La validación de skills puede devolver `name` y `description` analizados dentro de `data`.

### Añadir o eliminar un alcance

```bash
curl -X POST "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/scope" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Type: application/json" \
  -d '{
    "scope_type": "project",
    "scope_id": "{projectID}",
    "enabled": true,
    "ws_auto_select": false
  }'
```

| Campo | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| `scope_type` | string | Sí | `organization` o `project`. |
| `scope_id` | string | Sí | ID de la organización o el proyecto del alcance. |
| `enabled` | boolean | No | Habilita o deshabilita el artefacto en ese alcance. |
| `ws_auto_select` | boolean | No | Permite que Workspace seleccione automáticamente el artefacto en ese alcance. |
| `delete` | boolean | No | Usa `true` para eliminar el alcance. Por defecto es `false`. |

La respuesta es el artefacto actualizado con su lista `scopes`.

### Reintentar la creación de un artefacto

`POST /api/v1/app/artifact/{artifactID}/retry` elimina el artefacto original y crea uno nuevo con un cuerpo de creación completo. `organization_id` y `project_id` deben coincidir con los del artefacto original.

```bash
curl -X POST "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/retry" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "{projectID}",
    "type": "Folder",
    "name": "Q1 Support (retry)",
    "props": {}
  }'
```

La respuesta es el artefacto de reemplazo.

### Descargar contenido sin procesar

Sin la cabecera `Content-Disposition`, o con `Content-Disposition: inline`, la respuesta es una cadena con una URL prefirmada. Para un artefacto Link disponible, tanto este modo como `Content-Disposition: attachment` resuelven el artefacto original antes de devolver su URL o sus bytes:

```bash
curl "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/download" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}"
```

<Accordion title="Ejemplo de respuesta">
```text
https://storage.example.com/artifacts/artifact_doc_q1?signature=...
```
</Accordion>

Para recibir los bytes directamente, envía `Content-Disposition: attachment`:

```bash
curl "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/download" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Disposition: attachment" \
  --output q1-support-summary.txt
```

### Obtener contenido procesado

Este endpoint solo está disponible cuando el artefacto tiene un índice vectorial inicializado.
En la práctica, esto suele implicar documentos de conectores o artefactos con indexación ya completada.

```bash
curl "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/parsed-content" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}"
```

<Accordion title="Ejemplo de respuesta">
```text
# Q1 Support Summary
```

### Sincronizar un artefacto

Este endpoint se utiliza principalmente con artefactos de integración (SharePoint, Confluence, Claromentis o FileSystem).

```bash
curl -N -X POST "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/sync" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Accept: text/event-stream"
```

El cuerpo de la petición está vacío. La respuesta es un stream SSE emitido por el proceso de sincronización de la integración.

<Accordion title="Campos de eventos de sincronización">
| Campo JSON | Tipo | Presente en | Descripción |
| --- | --- | --- | --- |
| `type` | string | Todos los eventos | `sync_started`, `sync_progress`, `sync_completed` o `sync_error`. |
| `current_artifact_count` | integer | `sync_started` | Número de artefactos existentes. Por defecto es `0`. |
| `integration_item_count` | integer \| null | `sync_started` | Número total de elementos del proveedor cuando se conoce. |
| `integration_item` | object \| null | `sync_progress` | Elemento del proveedor que se está procesando. |
| `artifact_id` | string \| null | `sync_progress` | Identificador del artefacto afectado. |
| `artifact` | object \| null | `sync_progress` | Artefacto público afectado cuando se incluye. |
| `op` | string | `sync_progress` | `Added`, `Removed`, `Skipped`, `Updated`, `Recreated` o `Error`. |
| `progress` | number | `sync_progress` | Valor de progreso. Por defecto es `0`. |
| `message` | string | `sync_error` | Mensaje de error. |
</Accordion>

<Accordion title="Ejemplo de stream">
```text
event: SyncEvent
data: {"type":"sync_started","current_artifact_count":12,"integration_item_count":40}

event: SyncEvent
data: {"type":"sync_progress","artifact_id":"artifact_doc_q1","op":"Updated","progress":0.42}

event: SyncEvent
data: {"type":"sync_completed"}
```
</Accordion>

### Ingerir desde un artefacto de integración

`POST /api/v1/app/artifact/{artifactID}/ingest` inicia la ingesta desde el artefacto de integración indicado por `artifactID`. El cuerpo JSON requiere `project_id` y los demás campos dependen del proveedor. El ejemplo selecciona un espacio de Confluence; consulta la guía de cada integración para ver sus campos completos. La respuesta es un stream SSE.

<Accordion title="Parámetros del endpoint">
| Tipo | Nombre | Obligatorio | Descripción |
| --- | --- | --- | --- |
| Path | `artifactID` | Sí | Identificador del artefacto de integración. |
| Body | `project_id` | Sí | Proyecto de destino de la ingesta. |
| Body | Campos del proveedor | Condicional | Parámetros de selección o ingesta requeridos por la integración. |
</Accordion>

```bash
curl -N -X POST "https://{BASE_URL}/api/v1/app/artifact/{artifactID}/ingest" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "project_id": "{projectID}",
    "space_ids": ["ENG"]
  }'
```

## Comprobar artefactos enlazados antes de modificar

Usa este endpoint antes de cambiar un artefacto cuando necesites comprobar si otros artefactos enlazados dependen de él.

<Accordion title="Parametros del endpoint">
| Tipo | Nombre | Obligatorio | Notas |
| --- | --- | --- | --- |
| Query | `created_by` | No | ID de la cuenta que creó los artefactos a comprobar. |
| Query | `project_id` | No | ID del proyecto donde comprobar artefactos enlazados. |
| Query | `artifact_id` | No | ID del artefacto donde comprobar artefactos enlazados. |
</Accordion>

```bash
curl "https://{BASE_URL}/api/v1/app/resource/is-safe-to-modify?project_id={projectID}&artifact_id={artifactID}" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "x-org: {org_slug}"
```

<Accordion title="Ejemplo de respuesta">
```json
{
  "has_linked_artifacts": false
}
```
</Accordion>

## Errores y casos límite

- **Códigos de error de artefacto**: el campo `error` refleja fallos de ingesta:

| valor `error` | Significado |
| --- | --- |
| `InvalidExtension` | Extensión de archivo no admitida. |
| `MismatchedType` | El tipo de archivo no coincide con el tipo declarado. |
| `Malformed` | Archivo corrupto o ilegible. |
| `Encrypted` | Archivo protegido con contraseña. |
| `ParsingFailure` | El extractor no pudo analizar el archivo. |
| `MaxNodes` | Documento demasiado grande o complejo para el análisis. |
| `NoValidFile` | No se encontró un archivo válido. |
| `NoValidNodes` | No se pudo extraer contenido analizable. |
| `InternalError` | Fallo inesperado en la ingesta. |
| `Unknown` | Fallo no clasificado. |

Si `ingest_status` es `Error`, corrige el archivo y reintenta o sustituye el artefacto. Para artefactos de integración, corrige el origen y vuelve a sincronizar.
- **Advertencias**: `ingest_warnings` puede incluir valores como `BigSize`, `UnprocessableContent` o `NoContent` para indicar problemas no fatales.
- **400**: en creación falta `organization_id` o `x-org`, se usa `project_id` sin una organización seleccionada o ya hay una sincronización en curso.
- **401**: token ausente o no válido.
- **403**: permisos insuficientes o combinación no permitida de `organization_id` con `x-org`.
- **404**: artefacto o proyecto no encontrado.
- Para archivos de más de 250 MB, el backend conserva únicamente el registro del artefacto con la advertencia `UnprocessableContent`; no almacena los bytes subidos ni inicia la ingesta.
