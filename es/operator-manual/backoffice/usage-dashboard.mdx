## Resumen

Abre **Backoffice > Platform > AI Usage** para entender el consumo de IA por gateways, claves de API y actividad de Workspace. El panel permite identificar los mayores consumidores, comparar actividad a lo largo del tiempo e investigar un día o consumidor.

El acceso requiere permisos **Operator** o **Super Admin**. Deben estar habilitados el registro y el almacenamiento de [Audit Log](/es/operator-manual/configuration/features/feat-audit). Para inspeccionar solicitudes individuales, habilita también Activity Registry y usa [Activity explorer](/es/operator-manual/backoffice/activity-registry).

Las capturas muestran la interfaz en inglés con datos sintéticos de ejemplo. Los nombres de controles en esta página corresponden a esa interfaz.

![Panel de uso con datos sintéticos](/images/operator-manual/backoffice/usage-dashboard.png)

## Resumen y gráficos

Las cuatro tarjetas muestran **Recorded chat tokens**, **Chat requests**, **Attributed users** y **Requests completed** para los filtros seleccionados. Los tokens incluyen los valores de entrada y salida disponibles. Requests completed cuenta solicitudes sin un error registrado.

| Gráfico | Información |
| --- | --- |
| **Token consumption over time** | Tokens de entrada y salida diarios, por separado. La nota de cobertura indica cuántas solicitudes tienen ambos valores registrados. |
| **Requests over time** | Solicitudes diarias divididas por éxito o error registrado. |
| **Active users over time** | Usuarios atribuidos distintos por día. Los valores diarios no se suman para obtener usuarios únicos del periodo. |
| **Response performance** | Promedios diarios de latencia de respuesta y tiempo hasta el primer bloque. Excluye solicitudes sin tiempos registrados. |
| **Tokens by API key** | Principales claves de API por tokens de chat registrados. |
| **Token consumption concentration** | Los cinco mayores consumidores por usuario y el consumo restante, agrupado como **Others**. |
| **Most active users** | Principales usuarios por número de solicitudes. |
| **Files ingested**, **File searches**, **Embeddings** | Actividad diaria adicional de ingestión, búsqueda en archivos y embeddings, cuando está disponible. |
| **Tools recorded** | Llamadas registradas por herramienta: búsqueda de conocimiento y web, ejecución de código, consultas a bases de datos, creación de documentos y extracción web. |

Una llamada registrada no demuestra que la herramienta se ejecutara correctamente. La ausencia de registros también puede indicar que el registro estaba deshabilitado. Los gráficos adicionales muestran un estado no disponible cuando faltan sus datos.

### Clasificación de consumidores

**Who consumes the most** ordena consumidores por tokens registrados. Alterna entre **Users** y **API keys** para comparar tokens, solicitudes, tokens por solicitud y porcentaje del consumo.

La tabla muestra inicialmente los 10 primeros. **Show all** muestra toda la clasificación disponible y **Show top 10** vuelve a contraerla. Si la clasificación devuelta está limitada, aparece un aviso; expandir la tabla no elimina ese límite.

## Filtros

Usage y Activity explorer comparten filtros. Su estado se guarda en la URL para refrescar o compartir una vista con otro usuario autorizado de Backoffice.

<Tabs>
  <Tab title="Gateway">
Selecciona **All gateways** o uno o varios gateways.

Cambiar gateways conserva las claves de API compatibles y elimina las que quedan fuera del alcance. También restablece **Attributed user** a **All users**.
  </Tab>
  <Tab title="API key">
Selecciona **All API keys**, una o varias claves, o **Non API Users** para registros sin clave de API.

**All API keys** incluye solicitudes con y sin clave registrada, como las de Workspace. Una clave específica excluye solicitudes sin esa clave. Cambiar claves restablece **Attributed user** y puede ajustar los gateways para coincidir con las claves seleccionadas.
  </Tab>
  <Tab title="Attributed user">
Selecciona **All users**, una o varias identidades registradas, o **Unattributed** para solicitudes sin identidad de cuenta.

Los usuarios disponibles dependen de gateways, claves, estado y fechas. Cuando la lista alcanza el límite de 1.000 usuarios, reduce esos filtros para encontrar más usuarios.
  </Tab>
  <Tab title="Status">
Selecciona **All statuses**, **Success** o **Error**. Success significa que no se registró un error en el resultado de la solicitud.

Cambiar el estado restablece **Attributed user** a **All users**.
  </Tab>
  <Tab title="Date range">
El valor predeterminado es **Last 30 days**. Los presets disponibles son **Week to date**, **Month to date**, **Last 7 days**, **Last 14 days** y **Last 30 days**.

Puedes seleccionar un rango personalizado. No se permiten fechas futuras ni anteriores al **1 de enero de 2026**. Se normalizan las fechas invertidas. Los rangos superiores a **90 días** se acortan a los últimos 90 días terminando en la fecha final seleccionada.

Cambiar fechas restablece **Attributed user** a **All users**.
  </Tab>
</Tabs>

**Reset filters** restablece todos los gateways, claves, usuarios y estados, con los últimos 30 días. Cambiar filtros devuelve Activity explorer a la primera página. Estos filtros sustituyen los controles anteriores **Group by**, **Show** y **Keys**.

## Abrir un informe

1. Usa **Expand report** en un gráfico compatible para abrir su gráfico ampliado y tabla de desglose.
2. Selecciona un día, un estado de solicitud dentro de un día o un consumidor por usuario/clave para reducir el alcance.
3. Revisa las fechas y etiquetas de filtros del informe. Los informes de consumidores muestran consumo y rendimiento de solicitudes para esa identidad o clave.
4. Si Activity Registry está habilitado, usa **View requests** para abrir Activity explorer con los filtros del informe. Esta acción no se ofrece en informes de herramientas.

## Atribución y limitaciones

- Workspace usa sesiones en lugar de claves de API. Sus solicitudes contribuyen a los totales del gateway y pueden aparecer en **Non API Users**. La ausencia de clave no identifica por sí sola el origen de una solicitud.
- Las solicitudes de API se atribuyen al propietario de la clave; el usuario final de una aplicación puede ser distinto. Las solicitudes sin identidad aparecen como **Unattributed** y se incluyen en los totales.
- Si faltan nombres, se muestran emails o IDs registrados. Un aviso indica fallos parciales al cargar nombres de filtros; las métricas disponibles siguen siendo utilizables.
- Los tokens y tiempos ausentes no equivalen a ceros registrados. Los totales incluyen tokens disponibles y los promedios de tiempos excluyen datos ausentes.
- Si no hay solicitudes coincidentes aparece un estado vacío. Los errores al cargar el panel o informes ofrecen un control para reintentar.
- El panel y los informes son de solo lectura y no ofrecen exportación ni descarga. No hay filtros por organización o proyecto.
- Las métricas dependen de los logs conservados. [Hard Delete](/es/operator-manual/configuration/cron-tasks/hard-delete) y las políticas de retención pueden eliminar registros del historial disponible. Mantén sincronizados los relojes del despliegue.
