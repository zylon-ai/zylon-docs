---
title: "Audit Log"
---

Enable Audit Log events and traces with `features.audit.enabled`. This controls audit event generation. `logging.storage.enabled` controls internal persistence; `logging.delivery.syslog.enabled` and `logging.delivery.http.enabled` control external delivery separately. Audit events and storage are enabled by default; external delivery is disabled by default.

Audit events are emitted when the audit feature flag is enabled. Persisted audit history also requires internal log storage. Retention, syslog delivery, and HTTP delivery are configured through [Log Delivery and Storage](/en/operator-manual/configuration/features/log-delivery-storage).

### Configuration

| Key | Default | Values | Description |
| --- | --- | --- | --- |
| `features.audit.enabled` | `true` | `true`, `false` | Enables Audit Log events and traces. |
| `logging.storage.enabled` | `true` | `true`, `false` | Enables internal structured log persistence for audit history. |

### Example

```yaml
features:
  audit:
    enabled: true

logging:
  storage:
    enabled: true
```

For CLI-managed installations, merge these settings into `/etc/zylon/zylon-conf.yaml` and run `sudo zylon-cli sync`.

To connect a SIEM, follow [Send logs to your SIEM](/en/operator-manual/configuration/features/log-delivery-storage#send-logs-to-your-siem), which includes collector setup, delivery configuration, and a test event. Enabling the settings above alone does not forward logs externally.
