Models have finite context windows. Messages, instructions, tool definitions and tool results all use part of that window. Long output can also be shortened before it reaches the model.

## Compact a conversation

Standard, PTC and Creator include compaction. Use **Compact** in the command menu or `/compact` when available. Compaction replaces part of the active model context with a summary; it does not delete the project files or turn the summary into independent proof of earlier results. Recorded conversation history remains the place to inspect actual tool activity.

Minimal does not include the built-in compaction capability. Missing commands can reflect the mode rather than a broken installation.

## Preserve what matters

Before continuing, ask for a concise handoff:

> Summarize the goal, files changed, decisions, checks run, unresolved failures and the next concrete step. Include paths so I can verify the state.

Keep durable project rules in [instructions](/zylon-code/customization/project-instructions), and reusable workflows in [skills](/zylon-code/customization/skills). A chat summary is unsuitable as the only record of a credential, release approval or test artifact.

## Start a fresh task

Use a new conversation for an unrelated objective. A fork can retain useful history but shares files unless you prepare another checkout. Check current files and jobs after interruption or restart; earlier model descriptions can be stale. [Recovery](/zylon-code/troubleshooting/recovery) explains what to inspect.
