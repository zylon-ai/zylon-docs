Automation tasks let you schedule reminders and recurring work, such as a daily review of pending project tasks. They are built in. Standard, PTC and Creator can create reminders; Minimal and delegated subagents do not receive the reminder tools. The page is available from the sidebar without enabling another plugin.

## Create and verify a task

Choose **Automation tasks → New** and send a precise schedule request:

> Create a task named Daily review. Every weekday at 09:00 Europe/Madrid, read this project's checklist and report pending work. Do not edit files or install packages.

Check the saved task name, instruction, recurrence, time zone, next run and linked conversation. A recurring request should show a recurring rule, not a one-time date. The created task card can open its details in the right panel.

## Edit a task

Open the task and use **Rules** to change its name, instruction or run time. Choose daily, weekly, weekday, fixed interval, one-time or custom five-field cron timing, then **Save changes**. Changes remain a draft until saved; Cancel restores the saved values. A conflicting save requires reviewing the latest rule before retrying. Inactive tasks are read-only.

Use the list's search and **All**, **Enabled** or **Inactive** filter. **Records** shows saved deliveries, with older records loaded on demand. The conversation header also shows a clock when it has active reminders. The linked-conversation action opens the original chat when it is available; inspecting a task does not unarchive a chat.

## Keep the application running

The computer must remain awake and Zylon Code must remain running. There is no cloud worker or automatic wake-up. Work continues in the original conversation with its model and credentials.

A named zone such as `Europe/Madrid` follows daylight-saving changes for daily or weekly times; an elapsed interval does not. Intervals must be at least 60 seconds. After a restart, an overdue one-time task can arrive late, and a recurring task delivers only its latest missed occurrence.

## Interpret delivery and delete safely

A delivery record confirms that the scheduled message reached the conversation; read the conversation to check whether the agent finished its work. A crash during delivery can cause a duplicate; saved history is bounded and older records can be unavailable.

A delivered one-time task becomes inactive and remains under All or Inactive until deletion. There is no individual pause control. **Delete task** requires confirmation and removes the task and its saved delivery records. It retains the conversation and any message already queued there.
