Open **Plugins** in the sidebar. The page separates **Built-in plugin settings**, **Experimental plugins** and any additional installed plugins. **Settings → Built-in plugins** is the component inventory, where you inspect runtime status rather than enable each internal component separately.

## Enable a supplied feature

1. Find its card. Use **More** beside **Experimental plugins** for features such as worktrees, persistent terminals or session search.
2. Open the details and read what it adds, its prerequisites and its data handling.
3. Turn on its switch. Some entries need a download first; wait for the reported outcome and follow any restart notice.
4. Check the feature in a small task. A switch that is on does not prove a provider, credential or external application is ready.

Enabled features from More also appear on the main list. Turning one off removes it from that main list but leaves it available in More. Built-in feature data and credentials follow the rules in each guide.

## Configure and refresh

Shell, Agent execution and Subagent have their own forms under **Built-in plugin settings**. Change the values and choose **Save**; leaving a staged form discards unsaved edits. A plugin can also offer settings for individual components in its details.

Use **Refresh** to reload the list. A failed refresh can keep previously loaded cards visible with an error; retry before assuming they show the current state.

## Installation and removal

This Zylon build does not expose the general **Add plugin** installation dialog or a public plugin market. Ask your administrator about adding a package that is not offered. Creator can prepare a custom feature, but it still needs review and an approved installation path.

Switching off a feature keeps its installed package and any file changes it made. Plugins supplied with the application have no uninstall action. An on-demand entry can offer **Update** when its installed version differs from the version offered by your application. Keep a copy of its configuration and check the displayed result; a failed update can leave the package unavailable.

For errors, use [Plugin and MCP problems](/zylon-code/troubleshooting/plugins-and-mcp).
