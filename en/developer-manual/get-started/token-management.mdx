  <Tab title="Workspace Token">

    <Warning>
      Workspace token flow does **not** issue tokens for direct ZylonGPT API calls under `/api/gpt/v1/*`.

    ### Create a Workspace API token

    1. Sign in to Workspace as an account that can manage API tokens.
    2. Click the organization logo and open **API Tokens**.
    3. Click **Create API Token**, provide a name, and save.
    4. Copy and store the token value immediately. It is shown once.

    ![](/images/api-reference/images/token.png)
    ![](/images/api-reference/images/create-token.png)

    ### Verify token access

    Workspace endpoints under `/api/v1/app/*` require the `x-org` header.

    ```bash
    curl "https://{BASE_URL}/api/v1/app/me" \
      -H "Authorization: Bearer {API_TOKEN}" \
      -H "x-org: {org_slug}"
    ```

    <Accordion title="Example response">

        "id": "user_4b7c2a1d9e5f3c8b",

    ### Revoke a Workspace token

    Open **API Tokens** and click the trash icon on the token row.

    ![](/images/api-reference/images/revoke-token.png)

  <Tab title="Gateway Token (ZylonGPT)">
    This flow grants gateway-scoped access to the **ZylonGPT API** under `/api/gpt/v1/*`. It does not create a token for Workspace or Backoffice APIs.

    ### Create a Gateway token

    1. Open **Developer Console**.
    2. Select the target gateway.
    3. Click **Create API Token**.
    4. Enter a token name.
    5. Generate the token.
    6. Copy the token secret shown in the modal.

## API token scopes

Account token creation accepts these six serialized scope values:

| Scope | Access |
| --- | --- |
| `Read.All` | Account, token, gateway, Backoffice/meta, Workspace read/search, and the ZylonGPT read-only allowlist when the token carries `gateway_id`. |
| `ReadWrite.All` | Read and write access across the APIs, subject to the owner account's roles. |
| `Workspace.Read.All` | Workspace reads and search; Workspace mutations return `403`. |
| `Workspace.ReadWrite.All` | Workspace read and write operations. |
| `PrivateGPT.Read.All` | Only the ZylonGPT read-only allowlist for the selected gateway. |
| `PrivateGPT.ReadWrite.All` | ZylonGPT read and write operations for the selected gateway. |

When a token has multiple scopes, their grants are combined. The effective permissions are then limited to the permissions of the account and role that owns the token. A broad scope cannot elevate its owner, and a read-only API token remains restricted even when its owner is a SuperAdmin. These scope restrictions apply to API tokens only; interactive sessions are unchanged.

<Note>
  When an account token request omits `scopes`, it defaults to `Workspace.ReadWrite.All`. Sending an explicit empty `scopes` array returns `400`. Both `PrivateGPT.Read.All` and `PrivateGPT.ReadWrite.All` require `gateway_id`.
</Note>

`Read.All` does not require `gateway_id` at creation. Without that gateway context, the token can use its other read grants but cannot call ZylonGPT.

Gateway token creation accepts only `PrivateGPT.Read.All` and `PrivateGPT.ReadWrite.All`; requesting another scope returns `400`. For backward compatibility, the gateway token endpoint maps an explicit empty legacy scope list to `PrivateGPT.ReadWrite.All`.

For the ZylonGPT read-only endpoint list and read-write requirements, see the [ZylonGPT API overview](/en/developer-manual/build-with-zylon/zylon-gpt-api/overview).
