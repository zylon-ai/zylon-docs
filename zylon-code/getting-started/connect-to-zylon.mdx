Setup has two steps: verify the **Zylon domain and license**, then save a **developer token** for the models. A valid license does not replace an API key, and an API key does not activate a license.

## 1. Connect your Zylon domain

In the welcome dialog, enter **Zylon domain**, for example `https://zylon.example`, and select **Connect**. Use the HTTP or HTTPS address supplied by your administrator, including a port if required. Do not include an API path, credentials or query parameters.

| Address | Where it belongs |
| --- | --- |
| `https://zylon.example` | The Zylon domain in the welcome dialog or Settings → General. |
| `https://zylon.example/api/gpt` | The model API URL, which the application derives and displays automatically. |

Backoffice's setup instructions may show the full model API URL. If they show `https://zylon.example/api/gpt`, enter only `https://zylon.example` in **Zylon domain**.

The dialog closes after the application verifies a valid license that includes Zylon Code. You cannot skip this step. To change the domain later, open **Settings → General → Zylon connection**. If verification fails, see [License and access](/zylon-code/getting-started/license-and-access).

For a private certificate, a confirmation can show the server, fingerprint, issuer and validity dates. Verify those details with the administrator before using **Trust and connect**. Approval applies to that server certificate and domain.

## 2. Get a gateway API key

1. In Backoffice, open **Developer Console** and select the gateway your organization provides.
2. Open **API Keys** and select **New API Key**.
3. Enter a name, choose **Read & Write** and set an expiry date suitable for your work.
4. Create the key and copy it immediately. The secret is shown once.

Your account needs Developer access and access to that gateway. Ask an administrator to provide or enable them if necessary. The success dialog also includes Zylon Code installation instructions when downloads are available.

Use a **gateway** key, not a Workspace-only token. See the [platform token guide](/en/v1.58/developer-manual/get-started/token-management) for the token types and administration workflow.

## 3. Save the key in Desktop

Open **Settings → Models**, find the Zylon connection and paste the key in **Developer token**. The **Model API URL** is read-only; change its domain in General settings. Select **Save connection**.

The app checks the key by requesting the model list before saving. When editing a working connection, leave the token blank to keep the saved key. A failed discovery keeps the previous settings, token and catalog. **Refresh models** fetches the list again while preserving saved model customizations.

Open the model picker and choose an available model. The initial Zylon alias is `zylon/default`.

## 4. Test a small task

Choose a project folder and send:

> List the files in the project's top-level folder. Read one small text file and summarize its purpose. Do not change files or install anything.

Compare the tool result with the files on your computer. License verification authorizes the application; model discovery checks the connection; this task confirms that the selected model can reply and use a tool.

Keep the key in its credential field. Continue with [Your first task](/zylon-code/getting-started/first-task), or use [connection troubleshooting](/zylon-code/troubleshooting/setup-and-models) if a step fails.
